# CT 전체 검토와 현재 위치 — 2026-10-27

이 문서는 R0 착수 전 검토 기록이다. 이후 지원표·공개 검사·고정 소스 후보와 새 실행 결과는 [R0 결과](R0-INVENTORY-SOURCE-RESULTS.md)에 별도로 기록한다. 아래5a513 fingerprint와 검토 당시 수치는 과거 근거로 유지한다.

현재 CT는 **Intel Arc에서 제한된 기존 CUDA 프로그램의 연결·번역·실행을 검증한 초기 사용자 공간 호환 계층**이다. 실험용 가상 대상에서는 원본 소스로 빌드한 matrixMul EXE가 메타데이터 우회 DLL 없이 실행된다. 일반 CUDA 앱, PyTorch/CuPy/LLM, AMD, 배포 바이너리 전반 또는 성능 동등성이 완성된 것은 아니다.

다음 개발의 중심은 **지원표와 재현 기준 정리 → 현재 경로의 폭 확대 → 실제 사용 앱의 첫 실패 해결 → 다른 Intel PC 재현 → 성능 측정**이다. 모든 미지원 함수를 먼저 없애거나 임의의 완료율을 계산하는 방식은 사용하지 않는다.

- 이번 검토에서 Rust207 통과/기존 제외4, 별도 Runtime129 통과, Python224 통과, clippy 경고0/format, 정적 지원표 검사를 다시 실행했다.

## 최신 matrixMul 증거를 읽는 방법

- source revision/EXE/provider/실행 인자를 고정한 **upstream adjusted build**다. 모드별 원본 소스와 생성 EXE가 같다는 증거이며, 임의 배포 바이너리 무수정 실행 실증은 아니다.
- nominal 실행은 원본 EXE와 실제 CT Driver/Runtime 세 파일만 사용한다. 완료/sample PASS 근거다.
- 관찰 Driver 실행은 메타데이터를 변경하지 않으며 출력7168개 전체의 유한성·정확 일치를 외부 oracle로 검사한다. 계산/복사를 생략해도 sample은 NaN을 PASS로 오인하지만 외부 검사는 거부한다.
- capture/replay 합계14336개 비교는 동일 입력의 재실행이다. 새로운 입력 다양성14336개로 세지 않는다.
- Native ABI11/app8 경우, 기본 모드 거부, 잘못된 설정, 설정 불변성, 늦게 등록한 미지원 커널, DLL binding 오류가 포함된다. 초기화 순서 시험과 물리적인 DLL image preload 순서는 구분한다.
- 작은 두 shape/상수 입력은 실용 행렬 성능의 근거가 아니다. GPU global counter 기반 event 값에 host dispatch/idle gap이 포함될 수 있어 kernel-only 시간으로 사용하지 않는다.

현재 실행 근거: [virtual target](VIRTUAL-TARGET-RESULTS.md), [원본 커널](ORIGINAL-MATRIX-KERNEL-RESULTS.md), [후보 선택](CAPACITY-AWARE-FATBIN-RESULTS.md), [장치 정책](DEVICE-CAPABILITY-POLICY.md).
