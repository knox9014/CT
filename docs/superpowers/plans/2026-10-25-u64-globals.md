# Mixed-width CUDA global storage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Execute unchanged CUDA programs using scalar u32/u64 device globals through both CT Driver and Runtime on Intel Arc.

**Architecture:** Extend the existing typed global storage and context-owned native module. Every layer uses each symbol's actual width; launches and host symbol operations retain the same storage and lease/gate lifetime. Preserve existing rejection controls by replacing their now-supported u64 input with a still-unsupported array.

**Tech Stack:** Rust, Python unittest, CUDA12/nvcc, Windows x64, Level Zero, SPIR-V/Intel host-access extension; pinned existing tools only.

**Spec:** [approved design](../specs/2026-10-25-u64-global-design.md). User approved design on 2026-10-25. This plan awaits review; no product code changed.

## Global Constraints

- Runtime26/Driver39 exports; version1, zero external/constant/global flags, size4/8 scalar storage only.
- Direct typed ordinary/volatile u32/u64 named-global load/store only; no named offsets, arrays, constants, aliases, atomics, streams or new dependencies.
- Preserve exact u32 behavior and staged copy-error precedence in the spec, including failed/ambiguous/unknown lookup fallback bound4.
- One SymbolLease through initialization/action/output; context cache, retirement/drain and raw400/709 poisoning remain shared.
- Keep existing50 required IDs, add exactly2, target52; never relabel historical reports.
- Preserve11 user files, ignored raw evidence and managed historical checkout; existing draft PR only, no merge/release.
- Execute inline in the existing feature checkout, following the established workflow; final clean acceptance uses a separate managed checkout and new caches. Preserve CARGO_INCREMENTAL=0 and use a fresh ignored CARGO_TARGET_DIR for native DLL builds.

## Review Focus

1. A value with zero lower32 bits but nonzero upper32 must survive initialization, kernel update and host copy; Tasks1/4 assert exact64-bit results.
2. Mixed-width modules must reject copying5 bytes to a4-byte symbol even though another symbol is8 bytes; Task3 pins boundary/error/provider-call counts.
3. Native success with wrong size/alignment or overlapping symbols must not publish partial bindings; Tasks2/3 assert rejection and owned-handle cleanup.
4. New negative arrays must actually survive nvcc and registration, and fail with exact801; Task4 inspects source/PTX/stub/raw observations, not exit status alone.
5. Old manifests with recomputed hashes, stale tool recipes or wrong no-op observations must fail current evidence acceptance; Tasks4/5 add tamper cases and fresh replay.
