# M3i execution plan

Spec: [failure containment](../specs/2026-10-20-m3i-failure-design.md).
Inline execution, existing dedicated branch/cache, one independent final reviewer.

## Task 1: executable failure probes

- [ ] In ct-backend-intel/src/fault_tests.rs implement a private test-only Api
  alias with exact ABI stubs, thread-local call log/failure occurrence, byte
  buffer ownership and deterministic handles. Real backend methods are tested.
- [ ] Tests inject launch/copy/sync/cleanup errors, assert errors and no later
  native calls from poisoned contexts, preserve staging/device storage/handles,
  avoid double destruction, and isolate a second synthetic context. OOM/setup
  errors remain recoverable; DEVICE_LOST/REQUIRES_RESET must stop later work.
  Run cargo test -p ct-backend-intel; observe missing fatal handling failures.

## Task 2: close observed gaps

- [ ] Add shared fatal-result observation to Context and invoke on allocation,
  free, pre-submit kernel setup and module create paths as needed by RED tests.
  Allocate/free accept &mut Context if poison state must change; update CUDA
  callers. Do not poison for ordinary pre-submit OOM/argument errors.
- [ ] CUDA mapper tests assert2 for host/device OOM and999 for fatal/unknown
  native errors. Run workspace tests, rustfmt, Clippy; commit fixes and tests.

## Task 3: evidence and publication

- [ ] Run cargo test --workspace -- --include-ignored, Python19, real Arc
  M1/M2/M3h smoke scripts and native ABI checks. Verify production DLL exports
  unchanged with existing entrypoint check. Record precise fake/native limits.
- [ ] Update result/support/manifest docs, perform one fresh branch review,
  privacy and identity scans, push stacked draft PR and attach. No merge.

## Review focus

Check fake ABI and memory safety, cfg(test) exclusion, real code coverage rather
than mock behavior assertions, resource preservation at failure boundaries,
every poisoned path including zero-length copy, setup-fatal errors versus OOM,
partial cleanup/no retry, preserved original error and CUDA mapper limits.
Actual native device failure, driver restart, device-wide context invalidation,
real loader unload and recovery are not established by these tests.
