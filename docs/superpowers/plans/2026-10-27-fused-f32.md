# Fused F32 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans, with independent read-only review.

**Goal:** Preserve fused round-to-nearest-even binary32 multiply-add in actual CUDA consumers on Intel.
**Architecture:** Exact fma.rn.f32 IR operation lowers to OpenCL.std fma26; ordinary multiply/add retain ContractionOff and separate operations. Verify bits with an independent exact integer oracle and native CPU reference.
**Tech Stack:** Rust PTX/IR/SPIR-V1.0 Kernel/OpenCL1.2, genuine nvcc, Level Zero Intel, Python integer arithmetic.
**Spec:** User delegated implementation choices and requested the next matrixMul blocker. Scope below is the implementation decision.

## Contract and choices

Only scalar fma.rn.f32, three F32 operands and one F32 destination. No implied
rounding default, ftz/sat, F64/F16, packed, other rounding modes or mad aliases.
Use lazily imported OpenCL.std OpExtInst fma26; never a decomposed mul+add or mad.
Keep ContractionOff for other expressions. Do not add fast-math/denorm-flush flags.
NaN result classification is checked without requiring unspecified payload/sign.
Subnormal, overflow cancellation and signed-zero cases must be exercised on the
current GPU; evidence does not establish other-device floating-point behavior.

Alternatives: separate mul/add loses fused rounding; GLSL extension is the wrong
Kernel environment; software emulation is a larger future portability option.
Choose explicit OpenCL fma and actual validator/numerical execution evidence.

Ruling: matrixMul now translates completely and exploratory actual spirv-val
passes. Requalify triage as schema3/diagnostic_matrixmul_translation, hash positive
SPIR-V output and derive structural counts without claiming validation or app
execution. Keep validation=not_run in that diagnostic; perform separate actual
validator checks on the frozen output. The original application remains unrun.

Independent design review and frozen implementation review completed without
concrete blockers. The implementation review's initial dispatch failed with a
usage limit; retry after reset completed. Neither reviewer ran builds/tests/GPU.
